Mantenimientos con crud-kit

Describe los campos una vez y obtén la pantalla completa: listado con paginación, orden y filtros en el servidor, diálogos de crear, editar y eliminar, la misma validación en el navegador y en el servidor, y SQL parametrizado para SQL Server o MySQL.

crud-kit es el framework v2 de mantenimientos. Vive en packages/crud-kit como paquete independiente (no conoce nada de la intranet) y se conecta a la intranet con el adaptador clases/Framework/CrudKitIntranet/, que aporta la conexión, los permisos del menú y la pantalla.

Tu primer mantenimiento

Ejemplo real: Sectores v2 del sistema de picking (modulos/logistica/SectoresV2.php). Son cuatro pasos.

  1. Declara el CRUD

    Una función que devuelve la definición. El nombre de la tabla va calificado con la base ($GLOBALS['dbnameMIntranet']) para no depender de la base por defecto de la conexión.

    modulos/logistica/SectoresV2.php
    <?php

require_once 'clases/Framework/CrudKitIntranet/CrudKitIntranet.class.php';

use Ivandzb\CrudKit\Definition\Crud;
use Ivandzb\CrudKit\Definition\Field;

function sectoresV2Crud()
{
  return Crud::make('sectores')
    ->title('Sectores de entrega')
    ->table("{$GLOBALS['dbnameMIntranet']}.maestros.sectordespacho")
    ->fields(
      Field::text('idsector', 'Id Sector')->key()->onlyOnCreate()->filterable()->width('10%')
        ->rules(array('required' => true, 'maxLength' => 2)),
      Field::text('Descripcion', 'Título')->width('70%')
        ->rules(array('required' => true, 'maxLength' => 80)),
      Field::select('Activo', 'Estado', array(1 => 'Activo', 0 => 'Inactivo'))->width('20%')
        ->rules(array('required' => true))
    )
    ->permissions(array('delete' => 'E'))
    ->messages(array('loadingMessage' => 'Cargando sectores...'));
}
  2. Crea la pantalla

    Une la definición con la conexión y la URL de la opción de menú. Esa URL es la misma que pinta la pantalla y la que recibe las peticiones de datos.

    mismo archivo
    function sectoresV2Pantalla()
{
  return CrudKitIntranet::pantalla(
    sectoresV2Crud(),
    SingletonDB::obtenerDBMsSQL(),          // MsSQL_DB o MySQL_DB
    'index.php?modulo=logistica&file=mant_lista_picking&nombreOpcion=' . rawurlencode('Sectores v2')
  );
}
  3. Agrégala al menú del módulo

    La pantalla tiene los mismos métodos que los mantenimientos jTable de siempre (getHtml() y action()), así que entra en el flujo existente sin cambios.

    modulos/logistica/mant_lista_picking.php
    require_once 'modulos/logistica/SectoresV2.php';

// en getMenu():
$barraH_izquierda->addOpcionConSeguridad("Sectores v2", "Sectores v2", "{$index}&file=mant_lista_picking", Lista_picking_menu::OPCION_SECTORES);

// en rutas():
case "Sectores v2":
  $obj = sectoresV2Pantalla();
  break;

// el módulo ya hace:
if (!isset($_REQUEST['action'])) { $tdBloqueCentro->addHtml($obj->getHtml()); }
else { $obj->action($_REQUEST); }
  4. Pruébala

    Abre la opción, filtra, crea, edita y elimina un registro de prueba. Para ver la misma pantalla con la otra tecnología, agrega &render=quasar o &render=jtable a la URL.

Eso es todoNo escribes SQL, ni JavaScript, ni manejo de JSON, paginación o errores. El framework genera las consultas parametrizadas, valida y responde.

Cómo funciona por dentro

Al pintar

getHtml() genera el HTML y el JavaScript de la tabla (jTable o Quasar) a partir de la definición, con los botones que el usuario tiene permitidos.

Al pedir datos

La tabla llama a la misma URL con crud=<id>&action=list|create|update|delete|autocomplete. action() valida, consulta y responde JSON. Luego termina la petición.

SQL

Con table() el framework arma SELECT/INSERT/UPDATE/DELETE parametrizados. En SQL Server pagina con OFFSET … FETCH y en MySQL con LIMIT.

Partes

Definición (Crud, Field, Lookup) · servidor (Dispatcher, Validator) · datos (TableDataSource o tu repositorio) · renderizadores (jTable, Quasar) · puertos (conexión, permisos, textos).

Modificadores de campo

Se encadenan después de la fábrica: Field::text('x', 'X')->key()->filterable().

ModificadorQué hace

onlyOnCreate()Se escribe al crear y no se puede cambiar al editar (típico de claves que digita el usuario).
readOnly()Se muestra pero no se edita.

hideInForms()No aparece en crear ni editar.
computed()Se muestra pero nunca se graba (valores calculados por la consulta o el repositorio).
filterable()Agrega un filtro sobre la tabla. Por defecto compara igual; filterable(Field::FILTER_LIKE) busca por contenido.

rules([...])Reglas de validación; ver Validación.
options([...])Cambia las opciones de un select.

display($js) · input($js)jTableFunción JavaScript para pintar la celda o el control del formulario.
jtable([...])jTableCualquier opción de campo de jTable, tal cual.

Validación

Las reglas se declaran una vez y se aplican en el navegador (antes de enviar) y en el servidor (siempre). Un error se muestra junto al campo.

ejemplo
Field::text('placa', 'Placa')->rules(array(
  'required'  => true,
  'maxLength' => 6,
  'pattern'   => '^[A-Z]{3}[0-9]{3}$',
)),
Field::number('capacidad', 'Capacidad (m³)')->rules(array('min' => 0, 'max' => 90)),
Field::text('tramo', 'Tramo')->rules(array('in' => array('T1', 'T2')))
ReglaValorMensaje por defecto
requiredtrueEste campo es obligatorio.
minLength · maxLengthnúmeroEscriba al menos / máximo {value} caracteres.
numeric · integertrueEscriba un número / un número entero.
min · maxnúmeroEl valor mínimo / máximo es {value}.
patternexpresión regularEl formato no es válido.
inarreglo de valoresElija uno de los valores permitidos.

Para reglas que dependen de la base de datos (por ejemplo, "no repetir un municipio"), usa beforeSave() o confía en la restricción de la tabla: una clave duplicada se convierte en el mensaje duplicateKey, que puedes personalizar con texts().

Autocompletar (Lookup)

Un campo autocomplete guarda un código y muestra un texto. El Lookup dice de dónde salen.

dos formas de declararlo
use Ivandzb\CrudKit\Definition\Lookup;

// 1) Una tabla: columna del código y columna del texto
$sectores = Lookup::table("{$GLOBALS['dbnameMIntranet']}.maestros.sectordespacho", 'idsector', 'Descripcion')
  ->suggestOnly('Activo = 1');   // el buscador solo ofrece activos; el listado muestra todos

// 2) Una consulta con columnas id y text
$municipios = Lookup::query("
  SELECT t013.f013_id_pais + t013.f013_id_depto + t013.f013_id AS id,
         RTRIM(t012.f012_descripcion) + ' ' + RTRIM(t013.f013_descripcion) AS text
  FROM SiesaEnterprise.dbo.t012_mm_deptos t012
  INNER JOIN SiesaEnterprise.dbo.t013_mm_ciudades t013
    ON t013.f013_id_pais = t012.f012_id_pais AND t013.f013_id_depto = t012.f012_id
");

Field::autocomplete('CS_id_sector', 'Sector', $sectores)->filterable()->rules(array('required' => true))
  • El listado une el lookup y cada registro trae el texto en <campo>__text; la columna se ordena por el texto.
  • El buscador busca cada palabra escrita (todas deben aparecer en el texto).
  • Con un repositorio propio, devuelve tú el texto en <campo>__text (ver Viajes v2, campo estado).

Permisos I / M / C / E

En la intranet, los permisos salen de la opción de menú ($acceso): I insertar, M modificar, C consultar, E eliminar. Cada CRUD dice qué código exige cada operación:

ejemplo
->permissions(array('create' => 'I', 'update' => 'M', 'delete' => 'E'))
  • Una operación sin código queda permitida (si está habilitada). Sectores v2 solo exige E para eliminar.
  • Sin el permiso, el botón no se pinta y el servidor rechaza la petición: no basta con esconder el botón.
  • Las tablas hijas tienen sus propios permisos.

Textos y mensajes

Los textos vienen en español (packages/crud-kit/lang/es.php). Para una pantalla puedes cambiar los que quieras:

ejemplo
->messages(array('loadingMessage' => 'Cargando municipios...'))                 // textos de la tabla
->texts(array('duplicateKey' => 'Ese municipio ya tiene un sector asignado.'))  // textos del framework
ConClaves útiles
messages()loadingMessage, noDataAvailable, addNewRecord, editRecord, deleteConfirmation, serverCommunicationError
texts()duplicateKey, recordInUse, validationFailed, deleteSelected, deleteSelectedConfirm, filter, rule.required y demás rule.*

Para otro idioma, copia lang/es.php con la sigla que corresponda y cambia CrudKitIntranet::IDIOMA.

Tablas hijas (submantenimientos)

Una tabla hija es otro Crud que se abre debajo de la fila. Los campos enlazados filtran la hija y quedan ocultos en ella.

extracto de modulos/logistica/ListaPickingViajesV2.php
$listas = Crud::make('viajes-listas')
  ->title('Estados de las listas de despacho')
  ->readOnly()
  ->dataSource(new ViajesV2ListasFuente(new LogisticaListaPickingViajesListasDespachoRepository($db)))
  ->fields(
    Field::number('lista_despacho', 'Lista de despacho')->key(),
    Field::number('viaje', 'Viaje'),
    Field::text('estado', 'Estado')
  );

return Crud::make('viajes')
  ->fields(Field::number('viaje', 'Viaje')->key()->filterable(), /* ... */)
  //        nombre             título                 crud     hija => padre        ícono
  ->child('listas_despacho', 'Listas de despacho', $listas, array('viaje' => 'viaje'), 'fas fa-clipboard-list')
  ->jtable(array('openChildAsAccordion' => true));   // una hija abierta a la vez
  • Cada fila tiene un botón por hija, en las primeras columnas (después de la casilla de selección si la hay).
  • La hija se sirve por la misma URL con crud=viajes-listas; puede tener sus propias hijas.
  • El ícono es una clase de Font Awesome (fas fa-…), que la intranet ya carga.

Datos desde un repositorio

Cuando los datos salen de un procedimiento almacenado o de un repositorio existente, implementa DataSource. Si solo se consulta, extiende ReadOnlyDataSource y escribe solo list().

ejemplo de solo lectura
use Ivandzb\CrudKit\Data\ListQuery;
use Ivandzb\CrudKit\Data\ReadOnlyDataSource;

class ViajesV2ListasFuente extends ReadOnlyDataSource
{
  private $repositorio;

  public function __construct(LogisticaListaPickingViajesListasDespachoRepository $repositorio)
  {
    $this->repositorio = $repositorio;
  }

  public function list(ListQuery $query)
  {
    $viaje = (int) $query->filter('viaje');        // filtro o campo enlazado del padre
    $resultado = $this->repositorio->listarPorViaje($viaje, (int) $query->offset(), $query->limit() ?: 10);
    return array('total' => $resultado['total'], 'records' => $resultado['registros']);
  }
}
ListQueryDevuelve
filters() · filter('campo')Filtros ya validados (incluye los enlaces de una tabla hija).
sorting()Orden pedido, solo sobre campos declarados.
offset() · limit() · isPaged()Paginación.
params() · param('x')Parámetros crudos de la petición, para repositorios que ya los leen así.

Para escribir, implementa también create(array $valores), update(array $valores) (devuelven el registro grabado) y delete(array $claves). Los valores llegan ya validados.

RecuerdaDentro del repositorio, todo valor que llegue a SQL va con sql_query_params. Nunca interpoles filtros del usuario.

Ganchos y acciones propias

ejemplo
use Ivandzb\CrudKit\Server\ValidationException;

Crud::make('vehiculos')
  // Antes de crear, modificar o eliminar: lanza una excepción para cancelar.
  ->beforeSave(function (array $registro, $operacion) {
    if ($operacion === 'create' && $registro['capacidad'] > 90) {
      throw new ValidationException(array('capacidad' => 'Un camión no supera 90 m³.'));
    }
  })
  // Después de grabar (bitácora, avisos...).
  ->afterSave(function (array $registro, $operacion) { /* ... */ })
  // Cada registro antes de enviarlo al navegador.
  ->transform(function (array $registro) {
    $registro['capacidad'] = number_format((float) $registro['capacidad'], 2, '.', '');
    return $registro;
  })
  // Acción propia: &crud=vehiculos&action=recalcular
  ->action('recalcular', function (array $params, Crud $crud) {
    return array('Result' => 'OK');
  });

El mensaje de la excepción llega al usuario. Con ValidationException el error se marca en el campo.

jTable o Vue 3 + Quasar

La misma definición se pinta con jTable 2.4 o con Vue 3 + Quasar. Los datos, permisos y validaciones son los mismos.

DóndeCómoAlcance
CrudKitIntranet::RENDERIZADOR'jtable' o 'quasar'todos los CRUD de la intranet
En la definición->renderWith('quasar')esa pantalla (gana sobre la constante)
En la URL&render=quasarsolo esa carga, para comparar
  • jtable(), on(), display() e input() solo aplican en jTable; Quasar los ignora.
  • Quasar trae su propio Vue 3 dentro de assets/quasar/crud-kit-quasar.js y no choca con Vue 2, jQuery ni Bootstrap de la página.
  • Si cambias el componente Quasar: cd packages/crud-kit/quasar && npm run build && npm test.

Problemas frecuentes

SíntomaCausa probableQué hacer
"Error al conectar con el servidor."La respuesta no es JSON puro: algo imprimió antes (BOM, espacios o texto en config.php o un include).Abre la petición en la pestaña Red y mira el inicio de la respuesta.
Invalid table name: '.maestros…'$GLOBALS['dbnameMIntranet'] vacío cuando se construye la definición.Construye el CRUD dentro de la función que llama el menú, no al cargar el archivo.
La pantalla se pinta pero los datos no lleganLa URL de pantalla() no es la de la opción de menú.Usa la misma nombreOpcion con rawurlencode().
No aparece el botón Adicionar / EliminarFalta el permiso I / E en la opción, o la operación está deshabilitada.Revisa permissions(), readOnly() y disable().
Respuesta vacía con código 200 y lentitudXdebug con start_with_request=yes corta la respuesta.Reproduce por consola con XDEBUG_MODE=off antes de culpar al código.
